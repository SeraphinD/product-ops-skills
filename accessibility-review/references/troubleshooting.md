# Troubleshooting — accessibility-review

## Problem: Cannot determine the target platform
**Cause:** The artifact doesn't mention a specific technology or framework.
**Solution:** Ask the user directly: *"I can't determine the target platform from the artifact. Is this a web feature, native mobile (iOS/Android), or cross-platform (React Native/Flutter)?"* If the feature directory contains a DESIGN.md, check whether it was generated by `spec-to-design` (web) or `spec-to-mobile-design` (mobile).

## Problem: Feature has no UI
**Cause:** The feature is backend-only, a CLI tool, or an API service.
**Solution:** Note in the review: *"This feature has no user interface. Accessibility review is not applicable."* Do not produce a full review. If the feature has API responses consumed by a UI, note that the consuming UI should be reviewed separately.

## Problem: Color hex values not available for contrast checking
**Cause:** The SPEC or DESIGN doesn't specify exact color values.
**Solution:** If reviewing a SPEC, note that contrast cannot be verified without color values and recommend checking during DESIGN review. If reviewing a DESIGN that references a design system without inline hex values, scan the codebase for the theme file (same detection as `spec-to-design` Step 7) to extract actual values.

## Problem: RGAA mapping requested but criterion not in the standard mapping table
**Cause:** Some WCAG criteria have no direct RGAA equivalent (RGAA is narrower in scope).
**Solution:** Note the WCAG criterion and state: *"No direct RGAA mapping for WCAG {criterion}. The WCAG requirement still applies."* Consult the RGAA reference via `WebFetch` for edge cases.

## Problem: Prior review exists but platform has changed
**Cause:** The feature pivoted from web to mobile or vice versa after the last review.
**Solution:** Run a full review with the new platform's checklist. Note in the header: *"Platform changed from {old} to {new} since prior review — running full re-review with new standards."*

## Problem: Cross-platform feature needs both iOS and Android audits
**Cause:** React Native or Flutter features deploy to both platforms with potentially different accessibility behavior.
**Solution:** Review against both platform checklists. Group findings by platform when they differ. Use the cross-platform section to note framework-specific patterns (e.g., `accessibilityLabel` prop for RN, `Semantics` widget for Flutter).

## Problem: User disagrees with severity classification
**Cause:** Severity depends on context — a missing alt text on a decorative image is minor, but on a navigation icon it's critical.
**Solution:** Adjust the severity based on the user's context. Log the override to DECISION.md with the reasoning.

## Problem: WebSearch returns outdated WCAG guidance
**Cause:** WCAG 2.2 introduced new criteria not in WCAG 2.1.
**Solution:** Check which version the user targets. Default to WCAG 2.1 AA (most widely adopted). If the user needs 2.2, note the additional criteria (Focus Not Obscured, Dragging Movements, Target Size). Always verify the version in the W3C source.
